### New findings

**R3-M1 (medium). Mark done with a stale typed odometer clears the saved distance baseline, and one path does not say so.**
- Where: `src/app/service.tsx:107` and `src/app/service-reset.tsx:182` write `lastKm: km` and `lastKm: markDoneKm(v)`. For a stale typed figure `markDoneKm` returns undefined (`src/service/reminder.ts:176-178`). `garage.update` is a shallow patch (`src/vehicle/garage.tsx:242-244`), so the whole `service` object is replaced and `lastKm` is removed.
- Effect: the distance leg stops until the mileage is typed. On the Car tab and the Service page only the date leg shows. `distanceStale` is false because `kmLeft` is null (`reminder.ts:164`), so "Type the odometer again" does not show either. On the Service page the message says the mileage was not saved (`service.tsx:104`). On the reset path the success message does not mention it (`service-reset.tsx:184`).
- Fix: clearing the baseline is the right result (an old mileage would count from the wrong service), so keep it, but say so on the reset screen and show a prompt on the Car tile to type the mileage at the last service.
- Confidence: confirmed by code reading. Not run on a phone.

**R3-M2 (medium). Typing the same odometer again after 30 days saves nothing and still says "Saved".**
- Where: `src/app/service.tsx:60` compares the typed figure with `odo`, which is the figure already counted (`:35`). A stale typed figure typed again matches, so `odoChanged` is false and `odometerTypedAt` is not refreshed (`:63`). The reply at `:66-69` still says "Saved. The reminder counts from the last service."
- Trigger: a car that has not moved for 30 days or more, where the owner types the same figure. The footer at `:180` says "Type it again to count distance", which this does not do.
- Fix: refresh the typed figure whenever a typed value is saved (or whenever the saved figure is stale), and not only when the number changes.
- Confidence: confirmed by code reading. No test covers the Save path.
